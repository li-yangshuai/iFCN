# Pi 组合电路基准与旧证据资格

新实验统一使用 `tests/benchmarks_pi/v1/manifest.json` 指向的冻结文件，不直接使用仍在开发中的 `tests/benchmarks_f/TOY`、`MAJ` 或历史生成目录。原 TOY/MAJ 文件没有修改。

本清单整理可复核输入与已有证据，不预先给出算法成功率、面积/功耗优势、LLM 增益或论文录用结论。

## 冻结内容

`tests/benchmarks_pi/v1/{TOY,MAJ}/*.v` 保留当前顶层全部 30 个输入文件：TOY 17、MAJ 13。按文件字节去重为 29；按声明顺序匹配全部输入/输出真值表，得到 16 个函数组。这个分组不是 NPN 等价分类，也不是绝对独立电路数量。

同一函数的不同结构可以作为表示鲁棒性实验案例，但不得重复计为独立功能。`MAJ/xor5_r1` 与 `MAJ/xor5R` 是字节完全相同的副本；manifest 的 `exact_duplicate_of` 明确标注。`function_groups` 给出每组成员及固定的代表案例，便于在函数级与表示级分别汇总。

文件不以名称自动赋予规范。例如 `1bitAdderMaj` 实际是单输出的 `majority(input0,input1,NOT input2)`，不能称为具有和、进位双输出的完整全加器。

## 更正与保留决定

| 案例 | 冻结处理 | 验证依据 |
|---|---|---|
| TOY/xor2 | 模块头的 `in0,in1` 改为与声明一致的 `a,b`；赋值逻辑不变 | 原始与冻结标量表达式的全部真值表相同；冻结文件可接受标准前端检查 |
| TOY/RCA2 | `w8=a0 & b0`，`w19=n2 & cint` | 端口明确为 `a0,a1,b0,b1,cin → sum0,sum1,cout`；以独立整数加法参考穷举 32 组全部通过 |
| MAJ/RCA2 | 原样保留 | x/y 编号未说明算术位语义；标为来源定义的多输出函数，不与更正后的 TOY/RCA2 作为等价设计比较 |
| TOY/MAJ par_check | 原样保留 | 未提供外部奇偶检查规范；按实际组合函数记载，不擅自改为四输入 XOR |
| 其他文件 | 原字节保留 | 全输入穷举比较原始与冻结输出 |

TOY/RCA2 的更正有意改变原始逻辑，在 32 个输入中改变 12 个输出向量；不能宣称它与原始文件等价。更正后的规范为 `A=a0+2*a1`、`B=b0+2*b1`、`{cout,sum1,sum0}=A+B+cin`。例如 `A=0,B=2,cin=1` 输出 `sum0=1,sum1=1,cout=0`。

par_check 的实际函数为 `(a XOR b) XOR ((c AND NOT p) OR (NOT a AND p))`，MAJ 的 x0..x3 依声明顺序对应 a,b,c,p。它与常规四输入 XOR 不同，但未据文件名推断并修正意图。

30 例均有完整标量真值表校验，其中 20 例另有独立布尔或算术规范参考。源代码与冻结代码的 SHA-256、端口顺序、更正逐条说明、验证向量数、功能摘要以及真值表摘要均记录于 manifest。自带解析器只覆盖本套件所需的标量连续赋值子集；它不取代完整 Verilog 前端或器件物理验证。

## 实验读取契约

manifest 的路径相对于 iFCN 仓库根目录。

- `cases[].id`：稳定案例标识，如 `TOY/RCA2`。
- `frozen_relpath` / `frozen_sha256`：新实验实际输入及内容摘要。
- `source_relpath` / `source_sha256`：原始来源及冻结时摘要。
- `input_ports` / `output_ports`：输入与输出声明顺序。
- `function_group`：固定端口顺序真值表组。
- `exact_duplicate_of`：字节重复关系，非重复为 null。
- `change_notes` / `validation`：有意更正与穷举结果。

算法对照优先使用相同 `frozen_sha256`；跨表示比较还须匹配 `function_group`。函数级成功率每组只使用一个预先指定代表；表示级成功率可以使用全部案例，但应单独披露重复。LLM 对照须记录提示、模型、预算、调用轨迹、成功判据和独立验证结果。不能将工具命令退出码、两个数值引擎相互一致或布局文件存在直接计为物理功能正确。

## 历史证据资格

机器可读清单为 `tests/benchmarks_pi/v1/evidence_eligibility.json`。清单将历史数据与新实验隔开，未列出的旧产物默认不能进入新论文的性能统计，直至单独审核。

| 资格 | 主要旧产物 | 当前可支持的内容 |
|---|---|---|
| 废止并排除 | `paper/data/small_compaction_results.csv` | 仅归档来源。项目 2026-07-20 审计明确废止旧合法性检查，对应 Table 1、比较曲线及 c17 72→48 都要重新生成 |
| 未验证并排除 | `paper/data/large_fiction_results.csv` | 仅归档来源。旧大电路未经过当前硬端口检查，原记录也排除了其效益结论 |
| 待当前版本复核 | phase_pr 布线与器件映射 CSV、GCN-RL 历史摘要 | 证明存在工程运行记录；不能作为冻结 v1 的成功率或面积数据 |
| 仅数值引擎对照 | iFCN 36 与 hfut 25 的仿真摘要/CSV | 已记录配置下基准与加速引擎的数值比较和计时；不能代替 Verilog 到器件的功能验证 |
| 能耗未收敛 | 两个加法器旧能耗报告、历史 power 摘要 | 证明能耗导出阶段产生报告；不能支持收敛耗散能量、可信平均功率或功耗优化优势 |
| 仅工具集成 | Pi 首版 VALIDATION 记录 | SDK 工具接入证据；不能支持真实 LLM 自主任务完成率 |

清单没有生成新性能数字，也没有修改旧 CSV、报告或论文文件。CSV/JSON/TXT 历史结果绑定 SHA-256；VALIDATION 等说明文档标为动态上下文引用，不因正常更新说明而破坏结果复核。当前错误项较大的能耗记录需要独立的数值误差、启动区间和步长收敛检查后才能升级资格；命令成功不足以升级。

## 复核

在仓库根目录执行：

```text
python3 integrations/pi/curate_benchmarks.py --check
python3 integrations/pi/test_curate_benchmarks.py
```

第一条为只读完整复核。第二条共 8 项检查，覆盖表达式优先级、声明顺序独立性、拒绝无效依赖、RCA 算术修复、原始文件保持及去重统计；本机存在已安装的 Yosys 时，再对全部冻结文件执行标准 Verilog 读取、层次和结构检查。

测试还独立穷举比较当前 Pi 前端归一化的全部 30 例，检查归一化返回的端口元数据与声明顺序一致；现有 normal 后端中 10 例触发奇偶函数改写，改写后全部真值表与冻结输入一致。这一检查隔离执行现有改写函数，不执行布局或训练，也不等同于门级图、布线或器件波形验证。

首次生成使用 `python3 integrations/pi/curate_benchmarks.py`。v1 生成后拒绝内容覆盖；原始来源或生成规则改变时应复核差异并创建新版本。不要静默更新 v1 后继续混用旧实验结果。
