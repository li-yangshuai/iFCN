# Pi + iFCN 对照实验约定

本轮实验用于检验已实现功能并建立可复核的论文数据，不预设领域智能体优于通用 Pi，也不混入旧的已废止布局表。

## 输入与版本

统一读取 `tests/benchmarks_pi/v1/manifest.json` 与冻结 Verilog。清单记录原始/修正 SHA、端口顺序、独立参考和函数组；使用前执行 `python3 integrations/pi/curate_benchmarks.py --check`。30 个文件为表示级清单，不能称为 30 个独立函数。

实验记录运行前后的适配器、正常布局算法实现和实际执行二进制摘要。代码、冻结输入或运行时发生变化的批次不用于统一版本对照。原始失败、超时和工具轨迹全部保留，不能用事后重试替换原记录。

## 真实模型对照

复现入口：`integrations/pi/evaluate_agents.mjs`。默认只生成协议草案，不调用模型；`--run` 明确执行并使用机器已配置默认模型。每个 trial 使用新会话。脚本不修改模型、认证或项目设置。

```text
node integrations/pi/evaluate_agents.mjs --run
```

| 条件 | 做法 |
|---|---|
| 固定脚本 | 根据相同结构化任务字段执行预定工具流程，包括事先定义的错误路径回退 |
| 通用 Pi | Pi 原生系统提示，使用相同模型、四个 ifcn 工具和用户请求 |
| 领域主智能体 | 使用 agent.md 提示；其余模型、工具、参数、用户请求及预算与通用 Pi 相同 |

四类任务为普通映射、明确指定 Compact、输入不存在时使用给定备用路径、读取指定产物并报告验证边界。每类重复两次，共 24 个 trial，其中 16 个真实 LLM 会话。固定 seed 打乱试验顺序，最多两路并发。每 trial 上限 180 秒、12 次工具调用、3500 输出 tokens；后端命令预算 90 秒。

固定脚本是强的已知任务基线，不代表能够理解自然语言。其 token 指标不适用，不能把脚本零 token 当模型计费对照。两个 LLM 条件都能使用完整结构化工具，因此本对照主要测领域提示带来的增量；它不单独测量“有结构化接口”相对于原生命令行的贡献。

任务完成、指定参数/产物读取遵循、指标正确性、证据来源、验证边界、失败恢复和耗时分别评分。检查实际 manifest、文件存在性、SHA、QCA 元胞块与工具轨迹；不能凭模型自称完成或四工具覆盖就计为成功。按格式输出正确的失败说明，也不能算作器件映射已交付。

两次重复属于先导实验，不做统计显著性、普遍成功率或优越性断言。两种提示若结果相同，应如实报告。共享机器负载与供应商缓存可影响时间，报告同时保留后端阶段时间、总时间、输入/输出/缓存 tokens。

## 后端矩阵

复现入口：`integrations/pi/evaluate_backends.py`。默认冻结 30 个输入，分别选择三个明确后端，一次尝试、seed=1、180 秒上限，执行到 map；共 90 个任务。不使用 auto，不进行失败重试。

```text
python3 integrations/pi/evaluate_backends.py --timeout 180 --workers 2 --until map
```

可用 `--case TOY/xor2 --case TOY/1bitAdderAOIG` 缩小清单，用重复的 `--algorithm` 选择后端，或 `--until simulate` 增加数值引擎对照。每次写入全新的证据目录，包含 protocol.json、results.json、results.csv、final-checks.json 和每个生产作业的完整运行目录。

这是从同一冻结 Verilog 出发的端到端流程比较。normal 可能进行经等价检查的奇偶逻辑改写，其他后端使用的 DAG 因此可能不同；不能将面积差直接归因于同一 DAG 上的纯布局算法优势。Compact/June 的内部随机种子未由原算法公开，CLI 的 seed 字段不保证控制其全部内部行为。

面积和元胞数只对执行成功且通过报告列明检查的案例比较。报告全部失败，并用预先固定的同功能代表另作函数级汇总；不要从不同算法各自成功集计算均值后直接比较。运行时间含两路并发的共享负载，不作为严格单线程性能基准。

## 验证范围

冻结输入与前端改写通过的真值表检验、门级布线合法性、器件映射检查、数值引擎相互一致，是不同层次的证据。尚未验证的原 RTL—器件波形等价、时序对齐和能耗收敛保持明确标记。能耗字段可调用与数值准确、具有功耗优势不能混为一个结论。

新运行的 `result.json` 汇总实际指标与来源。模型只能称其实际读取过的产物为已核对内容，引用后端统计时应明确说明来源。

## 2026-09-05 先导实测

完整真实模型记录：`output/pi-validation/agent-comparison-2026-09-05T10-29-05-410Z/REPORT.md`。24 次尝试均保留，模型为本机默认 qwen3-vl-plus。

| 方法 | 映射实际完成 | 预设结构化交付正确 | 增加事后文本审计后完整正确 |
|---|---:|---:|---:|
| 固定脚本 | 8/8 | 8/8 | 8/8 |
| 通用 Pi | 7/8 | 5/8 | 5/8 |
| 领域 agent | 6/8 | 6/8 | 5/8 |

两种 LLM 各遇到一次连接错误、一次 Arrearage 账户状态拒绝。通用 Pi 有一个已完成后端的试验因随后连接错误未完成报告。没有删除这些试验，也没有把条件间差异解释为能力差异。正常返回的报告中，通用有一处来源指向不包含全部所报指标的文件，领域有一处将门级 tiles 写成 QCA 元胞。后者未被预设 JSON 评分覆盖，所以保留原计数，另列透明的事后文本审计。

结果不证明领域提示优于通用 Pi。固定脚本在这套已知结构化任务上表现最好；两种 LLM 提供了可验证的自然语言工具调用，但仍会产生报告措辞错误。

基于所发现的单位和来源问题，当前 agent.md 在本次试验结束后补充了明确的层级单位及逐指标来源规则。实验当时的提示原文和 SHA 保存在 `frozen-agent-source.md`，没有覆盖。由于模型服务返回账户状态拒绝，修订提示尚未进行真实 LLM 复测；不能用旧成绩代表修订版成绩。
